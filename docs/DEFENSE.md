# Тезисы для защиты

## Одна фраза

Ревизор проверяет строку отчета КФЗ по первичным документам: ИИ-агент читает каждый документ и цитирует
фрагменты, код сверяет суммы, а чат показывает для каждой цифры документ и место, откуда она взята, и
отделяет ошибку отчета от нехватки данных.

## Порядок демонстрации (4–5 минут)

Проверка набора идет 6–8,5 минут, поэтому показываются сохраненные проверки с настоящей моделью от
14.11.2026, и это проговаривается вслух. Новую проверку можно запустить в начале и вернуться к ней в конце.

1. Открыть `http://localhost:8000/app`, сверку «Этап 3, полный набор»: отчет не подтвержден, итог завышен на
   12 500,00 руб.; подтверждено 5, расхождений 2, недостаточно данных 8.
2. Раскрыть гр. 15: четыре документа, 245 000,00 + 318 298,10 + 270 000,00 + 300 000,00 = 1 133 298,10 руб.
   Нажать «Фрагмент»: сумма выделена на скане акта; страница открывается в отдельной вкладке.
3. Итог гр. 17 завышен на те же 12 500,00, а не на 25 000,00: расхождения не складываются.
4. Исключенные документы: копия акта ADM-27, акт ОРГ-0603 за июнь, акт ADM-75 по другому договору.
5. Открыть сверку «без ведомости за март»: оплата труда только частичная (4 456 674,83 руб.), ожидаемое
   значение и итог неизвестны, расхождение по гр. 15 остается. Это нехватка данных, а не ошибка отчета.
6. Спросить в чате «Объясни найденные расхождения»: ответ опирается на сохраненный результат и ссылается
   на фрагменты.

## Соответствие критериям

| Критерий | Чем закрыт |
|---|---|
| Извлечение данных и связывание | Агент читает отчет и все первичные документы (PDF, сканы, PNG, XLSX, DOCX) инструментами: страница, вырезка, повторный OCR, ячейки; значение принимается, только если процитированный фрагмент его показывает; договор, период и статья проверяются по документу |
| Расчет и агрегирование | Код на `Decimal`: несколько документов на показатель, помесячное покрытие ведомостей, единицы, знаки, округление half-up с допуском 0,01 руб. |
| Выявление расхождений | Статус и категория каждого показателя; итог не удваивает расхождение статьи; неполные данные дают «недостаточно данных», а не ложное расхождение |
| Трассируемость и отчет | Каждый вклад в сумму связан с документом и фрагментом: область скана с маркером, ячейка XLSX с формулой, цитата DOCX; заключение разделяет подтвержденные, ошибочные и непроверенные показатели |
| Неполные данные и надежность | Частичная сумма отделена от ожидаемого значения; нечитаемый документ и ошибки модели, таймаут, лимиты и отсутствие ключа завершаются понятным статусом |
| Развертывание | Dockerfile, Docker Compose, `.env.example`, README с запуском, настройками, внешними сервисами, архитектурой и двумя сценариями |

## Вероятные вопросы

**Зачем модель, если суммы считает код?** Формы документов разные, и правила их не покрывают. Модель
находит значения и цитирует фрагменты; принимает значение валидатор, а считает код. Ошибка модели
превращается в «недостаточно данных», а не в неверную сумму.

**Что уходит во внешний API?** Изображения страниц, распознанный текст, фрагменты и вопросы из чата. По
условиям задачи это допустимо только для открытых данных. Для закрытых документов указывается собственный
OpenAI-совместимый сервер; такая конфигурация пока не проверялась.

**Насколько это стабильно?** Модель недетерминирована. С итоговыми настройками полный набор совпал с
эталоном в обоих зафиксированных прогонах; в неудачных прогонах показатели уходили в «недостаточно
данных», а не в неверное «подтверждено» ([журнал](release-check.md)).

**Сколько стоит проверка?** Одна проверка набора из 23 документов: 6–8,5 минут, 50–57 запросов к модели,
около 0,6–0,9 млн входных токенов. GPU не нужен.

**Что дальше?** Все строки отчета за один запуск, модель на сервере заказчика, подтверждение спорной
трактовки бухгалтером с повторной проверкой, загрузка документов из 1С и ЭДО.
